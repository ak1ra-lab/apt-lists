# apt-lists

A small, read-only, repository-aware companion to `apt list`.

`apt-lists` answers one question that `apt list` cannot:

> Which installed package versions are currently provided by a specific APT
> repository?

```console
$ apt-lists --installed --repo https://deb.debian.org/debian-security/
PACKAGE  VERSION        ARCH   REPOSITORY
libbaz   3.1-2+deb13u1  amd64  https://deb.debian.org/debian-security/
seconly  2.0            all    https://deb.debian.org/debian-security/
```

## Why apt-lists?

`apt list --installed` tells you what is installed. `apt policy` tells you
which version APT would install next. Neither tells you which repository
currently provides the exact version that is already installed, and dpkg does
not record where a package came from.

That gap matters when you audit a system: which third-party repositories are
still actually providing installed packages, whether an update really came
from the security pocket, or whether an installed version is available from
any repository at all (a local `.deb` is not). The best answer libapt-pkg can
give is "these repositories in the current cache provide this exact
name+version+architecture", and `apt-lists` reports exactly that — never the
stronger claim that a package was *installed from* that repository. See
[provenance semantics](https://github.com/ak1ra-lab/apt-lists/blob/master/docs/provenance.md).

It is **not** a repository management tool. It never downloads package lists,
installs or removes packages, and never modifies APT configuration or the
dpkg database. It only reads the state that `libapt-pkg` already has: one
cache is opened per invocation, packages are iterated once, and filtering
happens in memory.

## Installing

The crate is published as [`apt-lists`](https://crates.io/crates/apt-lists).
It links against `libapt-pkg`, so a C++ toolchain and the APT headers are
needed:

```console
sudo apt install build-essential libapt-pkg-dev
cargo install apt-lists
```

Requirements:

* Debian (or derivative) with `dpkg`; not portable to non-dpkg distributions.
* `libapt-pkg` ≥ 6.0 (Debian 12+). Primary target: Debian 13 / APT 3.x /
  `libapt-pkg.so.7.0` (developed and tested against apt 3.0.3).
* Build: Rust 1.88+ and `libapt-pkg-dev` (for the headers).

To build a checkout instead:

```console
git clone https://github.com/ak1ra-lab/apt-lists
cd apt-lists
cargo build --release
# binary: target/release/apt-lists
```

### Shell completion

Completion scripts are generated by the binary. Install them for the current
user — no root required, and `/usr/share` belongs to the distribution's
packages:

```console
# bash (bash-completion loads this directory automatically)
mkdir -p ~/.local/share/bash-completion/completions
apt-lists --generate-completion bash > ~/.local/share/bash-completion/completions/apt-lists

# zsh (see the fpath note below)
mkdir -p ~/.local/share/zsh/site-functions
apt-lists --generate-completion zsh > ~/.local/share/zsh/site-functions/_apt-lists

# fish (loaded automatically)
mkdir -p ~/.config/fish/completions
apt-lists --generate-completion fish > ~/.config/fish/completions/apt-lists.fish
```

For zsh, add `fpath=(~/.local/share/zsh/site-functions $fpath)` to
`~/.zshrc` **before** `compinit`. The paths above follow the XDG defaults;
substitute `$XDG_DATA_HOME` / `$XDG_CONFIG_HOME` if those are set. Supported
shells: `bash`, `zsh`, `fish`, `elvish`, `powershell`.

For a system-wide install (distribution packaging or an administrator), bash
completions belong in `/etc/bash_completion.d/` and zsh completions in
`/usr/local/share/zsh/site-functions/`; do not write into `/usr/share`.

## Usage

```console
apt-lists --installed                          # all installed packages + providers
apt-lists --installed --repo <REPOSITORY>      # installed from one repository
apt-lists --repos                              # repositories known to the cache (+ package counts)
apt-lists <package>                            # all versions of a package + repositories
apt-lists <package>:<arch>                     # e.g. apt-lists foo:i386
apt-lists --all                                # all available package versions (default)
apt-lists --manual-installed                   # like `apt list --manual-installed`
```

Short forms: `-i` (`--installed`), `-r` (`--repo`), `-R` (`--repos`),
`-a` (`--all`), `-m` (`--manual-installed`), `-j` (`--json`).

Add `--json` for machine-readable output. `--repo` composes with `--installed`,
`--all` and package queries. A repository selector may be a full URI, a
hostname, or a host plus path:

```console
apt-lists --installed --repo https://deb.debian.org/debian-security/
apt-lists --installed --repo deb.debian.org/debian-security
```
